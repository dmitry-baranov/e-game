# Седьмой этап: интерфейс экспериментов и объяснение кода

Задание: [STRATEGY_AGENTS_STAGE7_TASK.md](STRATEGY_AGENTS_STAGE7_TASK.md). Работа выполнена в приложении с прежними URL и правилами игры; для экспериментов используется отдельный контур `:8081`.

## Реализовано

- Общая навигация между обзором серий, созданием, ходом серии, отчётом, игрой, парной оценкой и обучением. Общий адаптивный стиль в `src/main/resources/static/css/bot-experiments.css`, заголовки и пустые состояния для таблиц.
- Создание серии сгруппировано по цели, участникам, режиму, рынкам и политикам. Рынки выбираются чекбоксами с русскими названиями; предпросмотр использует прежний генератор. Список серий ограничен последними 20; полный обзор фильтруется по статусу и режиму и разбит на страницы по 50 записей.
- Ход серии показывает счётчики вместо строки JSON, управляющие действия по состоянию, последние 30 попыток и ссылку на отчёт. Сложный JSON отчёта и состояние ML-сервиса загружаются лишь при раскрытии деталей. Периодический опрос получает счётчики одним SQL и ограниченный список последних игр, а не всю историю серии.
- Отчёт серии показывает пригодность учебных циклов, результаты политик и срез по рынку/политике. Таблица игр имеет серверные фильтры по статусу и **всем восьми** рынкам с единого справочника, пагинацию и возврат из игры с сохранением параметров списка. Описательные показатели выделены отдельно от фильтрованной таблицы.
- Страница игры показывает краткий итог, сравнение всех ботов, дневные графики товаров и денег с отметками старта производства/рекламы, график и таблицу дневных продаж выбранных двух ботов, ссылки между решением, принятым циклом и дневными продажами. Для каждого плана видно, был ли он принят, отклонён из-за склада/кредита или предложен моделью с fallback; старые игры без журнала помечены как таковые. Продажи цикла суммируются только по реально записанным дням; неполный период помечен.
- Парная оценка содержит общее число пар и число пригодных пар, статусы обеих игр, seed и рынок; в финансовый результат входят только завершённые сравнимые пары. История обучения связана с сериями и парной оценкой существующими ссылками. Новые представления не записывают учебные данные и не запускают переобучение автоматически.
- В JavaDoc и комментариях на русском описан маршрут от контроллера и генератора до политики, проведения дня и отчёта. [Маршрут чтения](../src/main/java/ru/itis/diploma/experiment/bot/README.md) проходит через `experiment/bot/` и игровое ядро `game/`; правила 38 политик и параметры рынков описаны рядом с исходниками. [Текущая структура пакетов](../MODULES.md) показывает расположение контроллеров, моделей, репозиториев и сервисов.

## Проверка и границы

- `./mvnw -q clean package` прошёл с полным набором Java-тестов на отдельном PostgreSQL (не на рабочих томах). После добавления расчётов по циклу отдельно повторно прошли `BotAnalyticsNavigationIntegrationTest` и `AnalyticsTemplatesTest`. Интеграционный тест создаёт настоящую игру нового рынка и проверяет фильтры всех восьми рынков, отклонение неизвестного рынка и неправильного бота, SQL-данные и HTML-рендер отчёта/игры, сравнение двух ботов и администраторские права. Шаблонный тест проверяет пустые страницы и экранирование исходного JSON снимка.
- Экспериментальное приложение `:8081` обновлено после проверки отсутствия активных серий; `:8080` не перезапускался. Серия № 20 остаётся `DONE` с генератором `market-v3`; существующие тома БД и ML не изменены. Страница входа и статический CSS на `:8081` отвечают HTTP 200.
- Срез политик по рынкам — **описательная** статистика только завершённых игр; неодинаковые горизонты и распределение политик не дают причинного сравнения. Графики используют уже сохранённые данные; старый пропущенный журнал нельзя восстановить. Два бота сравниваются по дневным продажам, а все участники — в общей итоговой таблице; остальные временные ряды остаются по выбранному боту. Подробный отчёт серии рассчитывается по запросу, а не при частом опросе хода серии.
